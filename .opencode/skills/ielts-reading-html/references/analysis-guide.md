# 答案与解析写作规范

解析的目标：**让读者能在 10 秒内看懂“题干问什么 → 原文哪句证据 → 为什么是这个答案”**。不是写长篇赏析。

> 页面会在每题「解析」上方自动生成「原文回顾」：把该题 `keywords[].anchor.quote` 去重后，按段落标签列出英文证据句，并提供“定位原文”按钮。因此解析正文不必再整句抄原文；直接写“上面回顾的 X 段原句里……”，然后解释同义替换、矛盾或信息缺失即可。这样读者会先扫一遍原文，再看中文解释。

## 1. 四步结构

每道题按这个顺序写：

1. **题干要点**：用半句话概括题干在问什么（谁/何时/何地/比较/因果/态度）。
2. **定位**：用 `{{关键词}}` 标记 1–4 个定位词或同义替换。
3. **原文证据**：引用英文原句（可截取关键从句），说明它与题干的对应关系。
4. **判断/结论**：给出答案，并说明为什么其他选项/相反判断不成立。

中文模板：

```text
题干问……。定位到 X 段 {{关键词}}：原文说“……”。这里的 {{同义替换}} 对应题干的……；
但原文没有……/原文明确……，因此答案是……。
```

不用每道题都写满四步；简单题可以两步，但**必须**有原文证据和结论。

## 2. 关键词怎么选

优先选：

- **专有名词**：人名、地名、机构、研究名。
- **数字/时间**：1950s、200 metres、6 decibels、a third。
- **低频名词/动词**：amateur recordists、engine rumble、speculative。
- **同义替换对**：题干 `higher pitch` ↔ 原文 `shift its performance upwards`；题干 `protect habitats` ↔ 原文 `protecting the scrubby edges`。
- **限定词**：only、all、always、never、first、main、most、during、since、because、rather than。
- **否定/比较**：not、cannot、less likely than、more than。

不要选：

- 全文高频的普通词（the、people、study、bird）。
- 一个词单独看没有区分度的词（good、important）。
- 太长整句。关键词按钮应该短；证据句放在 `anchor.quote` 里，不放在 `term` 里。
- 与答案无关的“漂亮词”。

数量：1–4 个最舒服；超过 4 个会让解析变花。每道题至少 1 个。

`term` 与 `quote` 的分工：

- `term` 是解析里被高亮的短标签，如 `remains speculative`。
- `quote` 是原文中精确的一句话/从句，如 `The researchers are careful to say that this idea remains speculative.`
- 两者不必完全相同；`term` 可以是同义替换的概括，但必须自然出现在解析句子里。

## 3. 证据句（anchor.quote）规则

- **逐字**从 `case.json` 的段落正文复制，不要从记忆或 `transcript.md` 复制。
- 最小充分：一句话或一个从句，通常 8–40 词；超过 60 词构建器会警告。
- 包含答案所需的关键信息；填空题的引文必须包含答案词。
- 不要整段引用；整段会让定位高亮失去意义。
- 引文在段落中出现多次时，加 `occurrence` 指定第几次；否则默认第 1 次。
- NOT GIVEN 也要有引文：引用最相关的那句，然后在解析里说明“原文只说了……，没有说题干要求的……”。

## 4. 各题型写法

### TRUE / FALSE / NOT GIVEN

先判断关系，再写解析：

- **TRUE**：原文与题干同义改写，信息一致。指出同义替换。
- **FALSE**：原文与题干直接矛盾。指出矛盾点（反义词、否定、数字/范围冲突）。
- **NOT GIVEN**：原文没有足够信息判断。指出题干多出了什么条件（all、only、first、比较对象、时间），或原文只说了相邻但不同的信息。

解析里不要只写“原文没提到，所以 NG”。要写清楚**缺的是哪一个具体信息**。

示例：

```text
题干把发现者说成 professional scientists。B 段 {{amateur recordists}} 才是最早注意到差异的人：
In the 1950s, amateur recordists began noticing...。业余录音者与职业科学家直接矛盾，因此答案为 FALSE。
```

```text
原文只说 Marsh 团队比较了 {{12 populations}}，并单独指出 {{within 200 metres}} 的鸟更响；
但没有说明所有研究地点都在 200 米内。题干把局部条件扩大成全部，原文没有依据，因此答案为 NOT GIVEN。
```

### YES / NO / NOT GIVEN

和 TFNG 类似，但判断的是**作者/文章的观点**，不是客观事实。解析里要点出“作者认为/文章支持/作者没有表态”。

### Multiple Choice

1. 先用题干关键词定位证据句。
2. 说明正确选项与原文的同义替换。
3. 简要排除干扰项：偷换对象、过度绝对、因果倒置、原文未提、把 A 段信息套到 B 段。
4. 如果选项是句子，注意语法和主语是否匹配。

示例：

```text
题干问“为什么城市夜莺的音高更高”。C 段把原因归给交通噪音：低沉的引擎声会 {{mask the lower notes}}，
鸟被迫把歌声往上移。B 选项正是这个意思；A、D 是 D 段才讨论的配偶与灯光，C 项原文未提。因此选 B。
```

### Matching Headings

- 先读段落主题句（首句/末句/转折句），再匹配标题。
- 解析要说明**段落主旨**，不是某个细节。
- 指出易混标题为什么不对：范围过大/过小、只覆盖一个细节、方向相反。
- 证据句选主题句，不要选例子句。

### Matching Information

- 题干是“哪段提到 X”，解析要给出该段的具体证据，并说明其他段没有。
- 注意题目是否说明“You may use any letter more than once”。
- 证据句要包含题干的核心信息，不要只沾边。

### Matching Features

- 先框定人物/事物与观点的对应。
- 解析要写“某人说了什么”，并指出同名人物/相近观点的干扰。
- 证据句必须包含人物名或其指代。

### Matching Sentence Endings

- 先看语法：主语、时态、单复数、逻辑连接。
- 再看意义：结尾必须与前半句构成完整且符合原文的句子。
- 解析要同时说明语法排除和语义匹配。

### Summary / Sentence / Note / Table / Flowchart Completion

- 先读空格所在句，判断**词性**和**语法形式**（名词/动词/形容词/数字）。
- 用空格前后的词定位；注意同义替换。
- 答案必须是原文原词（按题目字数限制），并检查单复数、时态、冠词。
- 解析要给出原文原句，并说明为什么这个词填进去语法和意义都成立。
- 如果字数限制是 `NO MORE THAN TWO WORDS`，答案 `a third` 算两个词；`6` 算一个数字。不要擅自加词。

示例：

```text
空格前的 can 后面需要动词。C 段 {{mask}} 所在句说 Low-frequency engine rumble can mask the lower notes...，
其中 engine rumble 对应题干的 traffic noise，因此填 mask。
```

### Short Answer

- 答案必须直接回答疑问词（who/what/when/where/why/how much）。
- 用原文词，遵守字数限制。
- 解析给出定位句，并说明答案如何回答问题。

### Diagram / Table / Flowchart Labeling

- 先确定图中位置/流程顺序，再定位原文。
- 如果版式无法在 HTML 中还原，解析里用文字描述位置（如“图中最上方的箭头”）。
- 证据句要包含标签对应的原文词。

## 5. 干扰项与易错点

`trap` 只在确实有价值时写，1 句话即可。常见类型：

- **偷换对象**：把 A 的研究结论套到 B。
- **范围扩大/缩小**：some → all、only → most、within 200m → all sites。
- **绝对化**：always、never、prove、every。
- **因果倒置**：相关写成因果，或把结果当原因。
- **时间错位**：1950s 的发现 vs 后来的研究。
- **比较缺失**：原文没有比较，选项硬造比较。
- **情态差异**：may / suggest / speculate vs prove / certainly。
- **词性/语法不符**：填空题填了名词但空格需要动词。

## 6. 答案不确定时

- 先回到原文，确认是否真的没有信息；不要用常识补。
- 仍不确定时，`confidence` 设为 `medium` 或 `low`，解析里写清楚两种可能和你的倾向。
- 如果试卷有官方答案，以官方为准；与自己的推导冲突时，在 `meta.note` 或解析里标注“官方答案与原文推导存在冲突，建议核对”。
- 不要为了“看起来完整”编一个答案。低置信比假确定好。

## 7. 语言与篇幅

- 解析用中文；引用原文用英文。
- 每题 2–5 句，尽量不超过 120 字（中文）。
- 先给结论方向，再给证据；不要让读者读到最后一句话才知道答案。
- 关键词标记控制在 1–4 个；标记太多会打断阅读。
- 不要逐词翻译整段；只解释与题目相关的部分。
- 专有名词保留英文；必要时在括号里加简短中文。

## 8. 写完后自检

- 每道题的答案是否能被 `anchor.quote` 直接支持？
- 解析里的 `{{term}}` 是否都能在 `keywords` 找到同拼写的 `term`？
- `quote` 是否逐字出现在对应段落？
- 判断题的 FALSE 是否真的矛盾，而不是“没提到”？
- NOT GIVEN 是否明确指出了缺失的信息？
- 填空题答案是否符合字数限制和语法？
- 选择题是否排除了至少一个主要干扰项？
- 有没有把原文的 `may` 写成 `is`、`some` 写成 `all`？
- 低置信题是否标记了 `confidence`？
